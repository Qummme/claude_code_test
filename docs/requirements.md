# 自己管理アプリ 要件定義書

## 1. プロジェクト概要

### 1.1 目的

日々のタスク、習慣、振り返り、年間目標、スケジュール管理など、複数のツールに分散している自己管理情報を一元管理する個人向け Web アプリケーションを開発する。

### 1.2 背景

- 自己管理に必要な情報（タスク、振り返り、習慣、目標など）が複数のツールやメモに分散しており、一貫した管理ができていない
- 毎日の振り返りや習慣の記録を継続するための仕組みが必要
- 年間目標とその進捗を日々の活動と紐付けて管理したい

### 1.3 対象ユーザー

- 開発者本人のみ（シングルユーザー環境）
- Google アカウントでログインし、本人のみがアクセスできる

### 1.4 スコープ

**Phase 1（本開発の範囲）:**

- タスク管理、振り返り、習慣管理、年間目標・マイルストーン管理、スケジュール管理の全機能
- Google 認証、Firestore によるデータ管理
- レスポンシブ対応の Web アプリケーション

**Phase 2（将来の拡張）:**

- AI 連携（振り返り分析、タスク・予定の提案）
- 通知・ナッジ機能（スケジュール連動のプッシュ通知）
- 週次/月次レポート、統計グラフ、PWA 対応

**スコープ外:**

- マルチユーザー・チーム機能
- ネイティブモバイルアプリ（iOS / Android）

## 4. データモデル

### 4.1 データベース構成

Cloud Firestore を使用。全データはユーザー ID の配下にサブコレクションとして格納する。

```
/users/{userId}/
  ├── tasks/{taskId}
  ├── reflections/{dateString}
  ├── habits/{habitId}
  ├── habitLogs/{dateString}
  ├── goals/{goalId}
  ├── milestones/{milestoneId}
  ├── idealSchedule/{blockId}
  ├── dailySchedules/{dateString}
  └── settings/general
```

### 4.2 スキーマ定義

#### tasks コレクション

タスクを管理する。1 タスク = 1 ドキュメント。

```typescript
interface Task {
  id: string;           // ドキュメントID（自動生成）
  title: string;        // タスクのタイトル（必須）
  description?: string; // 詳細説明（任意）
  date: string;         // 対象日 "YYYY-MM-DD"
  status: 'todo' | 'done'; // 完了状態
  order: number;        // 表示順序
  createdAt: Timestamp; // 作成日時
  updatedAt: Timestamp; // 更新日時
}
```

**インデックス:** `date` (ASC) + `order` (ASC)

#### reflections コレクション

日次の振り返りを管理する。1 日 = 1 ドキュメント。ドキュメント ID に日付文字列を使用し、クエリ不要で直接取得可能にする。

```typescript
interface Reflection {
  date: string;         // 対象日 "YYYY-MM-DD"（ドキュメントIDと同値）
  items: ReflectionItem[]; // 振り返り項目のリスト（箇条書き）
  mood?: number;        // 気分（1〜5 の 5 段階、任意）
  createdAt: Timestamp;
  updatedAt: Timestamp;
}

interface ReflectionItem {
  id: string;           // 項目ID（UUID）
  text: string;         // 振り返り内容
  order: number;        // 表示順序
}
```

#### habits コレクション

習慣化したい項目のマスタデータを管理する。

```typescript
interface Habit {
  id: string;           // ドキュメントID（自動生成）
  title: string;        // 習慣のタイトル（例: "読書30分"）
  description?: string; // 詳細説明（任意）
  frequency: 'daily' | 'weekdays' | 'weekends' | 'custom';
  customDays?: number[]; // カスタム曜日指定（0=日曜〜6=土曜）
  isActive: boolean;    // 有効/一時停止フラグ
  order: number;        // 表示順序
  createdAt: Timestamp;
  updatedAt: Timestamp;
}
```

#### habitLogs コレクション

日次の習慣チェック結果を管理する。1 日 = 1 ドキュメント。

```typescript
interface HabitLog {
  date: string;              // 対象日 "YYYY-MM-DD"（ドキュメントIDと同値）
  completedHabitIds: string[]; // 完了した習慣IDの配列
  updatedAt: Timestamp;
}
```

**設計ポイント:** 1 日 1 ドキュメントに完了した習慣 ID をまとめることで、ダッシュボード表示時の読み取り回数を最小化（N 個の習慣 → 1 回の読み取り）。

#### goals コレクション

年間目標を管理する。

```typescript
interface Goal {
  id: string;           // ドキュメントID（自動生成）
  title: string;        // 目標タイトル（例: "JLPT N1 合格"）
  description?: string; // 詳細説明（任意）
  year: number;         // 対象年（例: 2026）
  category?: string;    // カテゴリ（例: "キャリア", "健康", "学習"）
  status: 'active' | 'achieved' | 'abandoned';
  order: number;        // 表示順序
  createdAt: Timestamp;
  updatedAt: Timestamp;
}
```

**インデックス:** `year` (ASC) + `order` (ASC)

#### milestones コレクション

目標に紐付くマイルストーンを管理する。

```typescript
interface Milestone {
  id: string;           // ドキュメントID（自動生成）
  goalId: string;       // 紐付け先の目標ID
  title: string;        // マイルストーンタイトル
  description?: string; // 詳細説明（任意）
  targetDate: string;   // 期限 "YYYY-MM-DD"
  status: 'pending' | 'in_progress' | 'completed';
  order: number;        // 目標内での表示順序
  createdAt: Timestamp;
  updatedAt: Timestamp;
}
```

**インデックス:**

- `goalId` (ASC) + `order` (ASC) — 目標別のマイルストーン一覧取得
- `status` (ASC) + `targetDate` (ASC) — ダッシュボードのアクティブマイルストーン取得

#### idealSchedule コレクション

理想の 1 日のテンプレートを管理する。

```typescript
interface IdealScheduleBlock {
  id: string;           // ドキュメントID（自動生成）
  startTime: string;    // 開始時刻 "HH:MM"（例: "06:00"）
  endTime: string;      // 終了時刻 "HH:MM"（例: "07:00"）
  title: string;        // ブロックタイトル（例: "朝の運動"）
  category?: string;    // カテゴリ（例: "運動", "仕事", "学習"）
  color?: string;       // 表示色（HEX形式）
  order: number;        // 表示順序
}
```

#### dailySchedules コレクション

日次のスケジュール（朝に予定を立てる）を管理する。1 日 = 1 ドキュメント。

```typescript
interface DailySchedule {
  date: string;              // 対象日 "YYYY-MM-DD"（ドキュメントIDと同値）
  blocks: ScheduleBlock[];   // 時間ブロックの配列（埋め込み）
  copiedFromIdeal: boolean;  // テンプレートからコピーしたかどうか
  updatedAt: Timestamp;
}

interface ScheduleBlock {
  id: string;           // ブロックID（UUID）
  startTime: string;    // 開始時刻 "HH:MM"
  endTime: string;      // 終了時刻 "HH:MM"
  title: string;        // ブロックタイトル
  category?: string;    // カテゴリ
  color?: string;       // 表示色
  status: 'planned' | 'completed' | 'skipped';
}
```

**設計ポイント:** 日次スケジュールのブロックはサブコレクションではなく埋め込み配列として格納。1 日のブロック数は 10〜20 程度で、常に一括で読み書きするため。

#### settings ドキュメント

ユーザー設定を管理する。ドキュメント ID は `general` 固定。

```typescript
interface UserSettings {
  displayName: string;
  timezone: string;         // タイムゾーン（例: "Asia/Tokyo"）
  dayStartTime: string;     // 1日の開始時刻 "HH:MM"
  theme: 'light' | 'dark' | 'system';
  language: 'ja' | 'en';
  goalCategories: string[];      // 目標カテゴリの一覧
  scheduleCategories: ScheduleCategory[];
}

interface ScheduleCategory {
  name: string;       // カテゴリ名
  color: string;      // 表示色（HEX形式）
}
```

### 4.3 セキュリティルール

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // デフォルトで全アクセスを拒否
    match /{document=**} {
      allow read, write: if false;
    }

    // ユーザー自身のデータのみアクセス可能
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }
  }
}
```

シングルユーザー制限を強化する場合（特定 UID のみ許可）:

```
match /users/{userId}/{document=**} {
  allow read, write: if request.auth != null
                     && request.auth.uid == userId
                     && request.auth.uid == 'YOUR_UID_HERE';
}
```

- シングルユーザーの利用では実質無料で運用可能

## 7. セキュリティ設計

### 7.1 認証方式

- Firebase Authentication を使用し、Google アカウントのみをログインプロバイダーとして有効化
- その他のプロバイダー（メール/パスワード、匿名等）は全て無効化
- セッションはブラウザに永続化（`browserLocalPersistence`）

### 7.2 認可方式（2 層セキュリティ）

**第 1 層: Firebase Authentication**

- Google アカウント認証のみ許可
- 認証されたユーザーのみ Firebase リソースにアクセス可能

**第 2 層: Firestore Security Rules**

- UID ベースのアクセス制御
- 各ユーザーは自身の `/users/{uid}/` 配下のデータのみアクセス可能
- シングルユーザー制限として、特定の UID をハードコードすることで他者のアクセスを完全に遮断可能

### 7.3 データ保護

- 全通信は HTTPS で暗号化（Firebase Hosting が自動で SSL 証明書を管理）
- Firestore のデータは Google Cloud の暗号化ストレージに保存
- API キーは環境変数（`.env.local`）で管理し、リポジトリにはコミットしない

## 8. 将来の拡張性

### Phase 2 機能候補

| 機能 | 概要 | 技術 |
|---|---|---|
| AI 連携（振り返り分析） | 振り返り内容を AI が分析し、パターンやフィードバックを提示 | Claude API / Gemini API |
| AI 連携（タスク・予定提案） | 過去の行動パターンや目標に基づき、1 日の予定やタスクを AI が提案 | Claude API / Gemini API |
| 通知・ナッジ機能 | スケジュールに応じたプッシュ通知で次のタスクや予定をリマインド | Firebase Cloud Messaging (FCM) |
| 習慣ナッジ | 習慣の実行時間帯にプッシュ通知で促し | FCM + Cloud Functions |
| 週次/月次レポート | 週・月単位での振り返りレポートを自動生成 | Cloud Functions |
| 統計グラフ | 習慣達成率、タスク完了率、気分の推移をグラフ表示 | recharts / Chart.js |
| 繰り返しタスク | 毎日/毎週/毎月の定期タスクを自動作成 | Cloud Functions |
| PWA 対応 | ホーム画面への追加、オフライン動作 | next-pwa |
| 画像添付 | 振り返りへの画像添付 | Cloud Storage for Firebase |

### 技術的な拡張ポイント

- **Cloud Functions:** バックグラウンド処理（レポート生成、通知送信、AI 分析）の実行基盤
- **Firebase Extensions:** 追加サービスとの統合
- **データモデル:** 拡張に備え、各ドキュメントに柔軟なフィールド追加が可能な構造
